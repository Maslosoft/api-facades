# Improvements

## Parameters in headers

The real life OpenAPI may have parameters are passed in headers, defined like this in the following part of JSON schema:

```json
{
  "name": "x-api-key",
  "in": "header",
  "required": false,
  "schema": {
    "anyOf": [
      {
        "type": "string"
      },
      {
        "type": "null"
      }
    ],
    "title": "X-Api-Key"
  }
}
```

## URL Modules and Verbs Simultaneously

The example for this issue is the following file:

`examples/openapi.02.json`

Some APIs have URLs that define both modules and verbs, that is the root
URL returns something, and it's sub URL's are a different enspoints.

For example, endpoint defines routes:

```
GET /api/invoices/
GET /api/invoices/items
```

Current generator results in class having two same properties of `$invoices`,
one for module and one for verb.

To fix this, the module itself should have verb-like methods that will
return calls from acutal verb.

For example, in such case, the InvoiceModule class should have methods same as defined verbs,
and have generated verbs assigned as `_own`, and to avoid conflits, such verbs class names should be
placed in separate namespace: `ModuleVerbs` instead `Verbs`.

```php
final class InvoicesModule extends GenericModule
{
...
    public function __construct(private Client $client)
	{
	// Verbs and modules assignements
        $this->_own = (new InvoicesVerbs($this->client))
	// ... other onces
	}
	
	public function get()
	{
	    // Pseudo code example
	    return $this->_own->get()
    }
}
```

So then it could be used like this:

```php
$client = new Client();
$client->invoices->get();
$client->invoices->retry->post(1);
```
